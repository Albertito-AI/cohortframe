# CohortFrame source provenance

## Canonical product home

The canonical CohortFrame application, issues and releases are maintained in
[Albertito-AI/cohortframe](https://github.com/Albertito-AI/cohortframe), a private
product repository created on 28 October 2026 at the founder's instruction.
Atlas Agent School remains the founding educational community. Its curriculum,
admission decisions and maintainer qualification process stay with the school.
Actual private learner and assessment records remain outside Git.

## Original implementation

The initial application was incubated in the private Atlas Agent School project:

- Repository: `Albertito-AI/atlas-agent-school`.
- Source pull request: [#15](https://github.com/Albertito-AI/atlas-agent-school/pull/15).
- Source commit: `ea4631b9d2a8eaff19e5557b9c65449f06ddbd95`.
- Source directory: `projects/cohortframe/`.
- Source tree: `555a0ffc587473edadd022de143586c8840584ca`.
- Extracted files: 24; each file's Git blob identifier, byte size and SHA-256
  matched before launch-document changes.

The directory's contents became this repository's root. Its own package-level
workflow became `.github/workflows/tests.yml`; the school's wrapper workflow and
institutional repository history were not imported. Runtime code, tests and the
versioned CLI/project contract were preserved in the extraction.

Launch edits identify the canonical product repository, explain how to install
the separate wheel asset and distinguish the original validation receipts from
the dedicated release verification. The product is an original implementation,
not an OpenFilm source fork. [NOTICE.md](../NOTICE.md) retains its distribution
and dependency terms.

## Educational continuity

The school references the product and its frozen releases. Generic handover
requirements remain in [SUCCESSION.md](SUCCESSION.md), while approval of a
particular cohort and any delegated access require the school's own decisions.
An ordinary authorised product client does not need school enrolment.

Repository separation does not itself transfer maintenance to students. The
founder-directed development workflow remains the current maintainer.
